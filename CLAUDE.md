# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

An **unofficial** MV3 browser extension (Chrome/Edge + Firefox) that translates the
Hungarian-only Billingo invoicing UI (`app.billingo.hu`) into English or French,
live and in place. There is **no backend**: a static, hand-curated dictionary ships
inside the extension and a content script substitutes text nodes and a few
attributes in the DOM.

Two halves, with different rules:

| Half | Path | Module system | Ships to users |
| --- | --- | --- | --- |
| Runtime extension | `src/`, `dict/`, `manifest.json`, `icons/` | **classical scripts** (no ESM) | yes |
| Build/capture pipeline | `tools/`, `scripts/` | **ESM** (`"type": "module"`) | no |

## Commands

```bash
npm install                                  # jsdom, acorn, playwright (required for tests)
npm test                                     # node:test over tests/**/*.test.js

node tools/extract-bundle.js <cookie-jar>    # Nuxt bundle → HU strings → tools/capture/bundle.tsv
node tools/crawl-rendered.js <cookie-jar>    # passive route sweep → tools/capture/sweep.tsv
node tools/crawl-interactive.js <cookie-jar> # dropdowns/editor states → tools/capture/interactive.tsv
node tools/build-shards.js                   # capture/*.tsv + dict/{en,fr}.json → dict/<lang>/*.json
                                             #   safe with no capture; --allow-shrink to force past a guard
node tools/mine-html-keys.js                 # v-html dict keys → matchable per-segment pairs (proposal only)
node tools/diagnose-extension.js <cookie-jar># load the extension for real, report residual HU strings
node scripts/build-icons.mjs                 # needs `npm i sharp` ad hoc; not a project dependency

npm run package                              # dist/{chrome,firefox}/ + one .zip each, validated
npm run package:crx -- --key crx-key.pem     # signed .crx + updates.xml + policy bundle
                                             #   CI reads the key from CRX_PRIVATE_KEY instead
npm run lint:ext                             # Mozilla's web-ext lint over dist/firefox (via npx)
```

## Packaging & install

`scripts/package.mjs` builds both targets from an **allowlist** of the runtime files, never
"the repo minus some things" — a denylist ships whatever gets added next. It validates the
whole payload *before* writing a byte (content scripts, icons, popup references,
`web_accessible_resources` patterns that match nothing, an ESM `import` that would stop Chrome
evaluating a content script, shards named by `_index.json` but absent in a language). The ZIP
writer is ~60 lines of `zlib` so the build works offline; `web-ext` is only needed to **sign**
for Firefox. `dict/_rejected.json` is build metadata and is excluded explicitly, because the
`dict/*.json` web-accessible glob would otherwise serve it.

Two manifest facts drive this and are easy to regress:

- **`strict_min_version` must stay ≥ 127.** Before Firefox 127 the host permission behind
  `content_scripts` was not granted at install, so the add-on installs and translates nothing.
  `firefoxManifest()` asserts it rather than silently rewriting the committed manifest.
- **`gecko.data_collection_permissions` is required** — `{"required": ["none"]}`, the honest
  value here: no network calls, no telemetry. AMO already warns without it.

Installation differs per browser, and the README spells it out: Chrome blocks a local `.crx`
on Windows/macOS, so it is an unpacked folder at a **stable path** (on WSL, a Windows path —
`\\wsl.localhost\…` breaks whenever WSL stops) or the Web Store. **Firefox only installs
extensions signed by Mozilla**; for private use the route is AMO *self-distribution*
("unlisted"), which signs the build without listing it publicly.

### Releasing (`.github/workflows/release.yml`)

Triggered by pushing a `v*` tag; `workflow_dispatch` runs a **dry run** by default (test,
build, lint, no submission) because signing burns an AMO version number that cannot be reused.
The workflow tests and lints *before* signing for the same reason: a broken signed build
cannot be corrected in place.

- **Firefox** — `web-ext sign --channel unlisted`, credentials passed through
  `WEB_EXT_API_KEY` / `WEB_EXT_API_SECRET` (env, never argv, which is visible to other
  processes). Needs the `AMO_JWT_ISSUER` and `AMO_JWT_SECRET` repository secrets; the step
  fails loudly without them, since signing is the point of the workflow. The signed `.xpi`
  filename is generated by `web-ext`, so it is globbed, not guessed.
- **Chrome** — there is **no signing step**: the Web Store signs on publish, and its API can
  only *update* an item, never create the listing. The step therefore **skips itself** when
  the five `CHROME_*` secrets are absent, so a Firefox-only setup needs no configuration.
  Both the upload and the publish response are inspected, because `curl` exits 0 on an HTTP
  4xx unless told otherwise and the Web Store also reports failures inside a 200 body.
- **Chrome, self-hosted** — `scripts/crx.mjs` signs the *already validated* Chrome zip into a
  CRX3 with our own RSA key (`CRX_PRIVATE_KEY`, skips itself when absent) and emits
  `updates.xml` plus a policy bundle. Hand-rolled like the ZIP writer, and verified
  byte-for-byte against `google-chrome --pack-extension` on the same key. **The extension ID
  is derived from the key** (first 16 bytes of SHA-256 over the DER SPKI, nibbles mapped to
  `a`–`p`), so rotating `CRX_PRIVATE_KEY` creates a *different* extension and orphans every
  install. Chrome needs a policy to accept a non-store ID at all: `ExtensionInstallForcelist`
  (Chrome installs and updates it, user cannot remove) or `ExtensionInstallAllowlist` (only
  unblocks the ID, manual install, no auto-update). `policyFiles()` emits both for
  Windows/Linux/macOS with the real ID baked in — a placeholder ID fails as an extension that
  never appears, with no error anywhere. Forcelist is viable here **because this repo is
  public**: a private repo must fall back to the allowlist, since Chrome's updater cannot
  authenticate to fetch a private repo's release assets.
- The tag must equal `manifest.json`'s version. That guard exists so a mismatch fails in two
  seconds instead of surfacing as an opaque AMO rejection after a green-looking build.
- **A tag push runs the workflow file from the tagged commit, not from `main`.** Tagging a
  commit older than `release.yml` fires nothing at all — no run, no failure, no notification.
  This is how the first 1.0.0 release produced no artifacts.

The build steps are duplicated between `ci.yml` and `release.yml` rather than shared through
`workflow_call`: the release job needs the artifacts in its own workspace to sign them, and
the indirection costs more than the five repeated lines save.

`<cookie-jar>` is a Netscape-format jar for an authenticated Billingo session. It is
never committed; without it the capture tools cannot run.

## Runtime architecture

Load order is fixed by `manifest.json` → `content_scripts.js`; each file is an IIFE
that publishes onto `globalThis.BillingoTranslator`. **Never add `import`/`export` to
`src/`** — Chrome evaluates these as classical scripts and tests load them through
`vm` (`tests/load-script.js`).

| File | Responsibility |
| --- | --- |
| `src/translator.js` | Layered lookup (exact → whitespace → punctuation → patterns) + hit/miss stats. No DOM, no `chrome.*`. |
| `src/dom-walker.js` | TreeWalker over text nodes + translatable attributes; remembers originals; `MutationObserver`. |
| `src/shard-loader.js` | Route → zone → lazy `fetch(dict/<lang>/<zone>.json)`, merged into one object, load-and-keep. `ensureAll()` sweeps every zone. |
| `src/spa-router.js` | Detects SPA navigation (polling is the reliable path — see below). |
| `src/content.js` | Wiring, storage, popup messaging, monolithic-dict fallback. |
| `src/popup.{html,js,css}` | Language radiogroup, live coverage %, and export of the untranslated strings (copy / download JSON). That export is the **only feedback loop from real usage back into the dictionary** — `getStats` answers with `uniqueMisses`, the pathname and the extension version, capped so a pathological page cannot make the payload unbounded. `createStats` remembers the translations it emitted and refuses to count them as misses, because Bootstrap renders `.tooltip-inner` from the already-translated stashed `title`, so our own output comes back as a fresh text node and used to pollute the export with English and French. |

### Invariants you must not break

These exist because a naive implementation froze the real Billingo app. Changing
`src/dom-walker.js` without preserving all of them is a regression:

- **Originals are stashed in WeakMaps** (`originalText`, `originalAttrs`) so language
  switching and restore-to-Hungarian work with no reload.
- **`ourTextWrites` / `ourAttrWrites` guard** — the observer must ignore mutations we
  caused, otherwise it loops on its own output.
- **No-op-by-equality** — never assign a value equal to the current one; this is what
  makes re-walking idempotent and safe to run concurrently with the observer.
- **Time slicing** (`runSliced`, `SLICE_SIZE`) — `walkAndTranslate` may return *before*
  finishing. Callers must not assume synchronous completion.
- **`walkGen`** — a newer full walk aborts an older one. Mutation processing passes no
  `gen`: it is incremental and must neither cancel nor be cancelled by a full walk.
- **Volatile-node cap** (`RETRANSLATE_CAP` within `RETRANSLATE_WINDOW_MS`) — a node the
  framework keeps reverting is abandoned. Only *external* reverts count, so a user
  switching languages never trips it.
- **Flood circuit-breaker** (`FLOOD_THRESHOLD` records/s → disconnect, cooldown, resettle).
- **Empty dictionary value means miss**, never blank output — an untranslated key
  (`""`) must leave the Hungarian text visible. This holds at every lookup layer.
- **`recordMiss` only counts what could be text** (`isReportableMiss`). Amounts, UUIDs,
  dates, lone punctuation and truncated fragments are not untranslated strings: counting
  them made the popup export 57 % noise on a real page (169 of 310) and understated the
  coverage percentage, which is derived from `misses`. The rule is **structural, never
  semantic** — strip digits, separators, currency symbols and currency codes, then require
  a surviving two-letter run (or a standalone single letter, which is a real label like
  `x`). Names are deliberately **not** filtered: `Példa Péter` and `Szállító adatok` are
  both two Hungarian-looking words, so a rule that dropped one would hide real UI text.
  Accent-less Hungarian must keep being reported, since capture already cannot see it.

### Lookup layers (`src/translator.js`)

Exact match is layer 1; everything after it exists because Billingo renders text
the dictionary cannot hold verbatim. **The file's own header comment is the
authoritative list** — it gives every layer, the execution order, and *why* that
order (most reliable first, most destructive last; layer numbers are stable
identities, so 5 executes before 4). Read it before touching the cascade. In short:
exact → whitespace → trailing punctuation → case variant → patterns →
parenthetical tail → separator split.

Layers 2 and 4 use a derived index; layers 1, 3, 5, 7 and 8 read the dictionary
live through `lookupPlain`. `createTranslator(dict, { lang })` takes the active
language, because French needs a space before `! ? ; »` when a layer re-composes
punctuation — the shipped values use a **regular** U+0020, not a NBSP. Omitting
`lang` preserves the language-agnostic behaviour.

**`translate.refresh()` must be called whenever the shard loader merges a new
zone**, or the pattern index goes stale. `src/content.js` does this after
`ensureZoneForRoute` (only when it returned `true`) and after `ensureAll`.
Rebuilding is a full dictionary pass (~30 ms over ~8 k keys), so do not call it
per route change unconditionally.

Two rules every layer must respect: an empty dictionary value is a **miss**, never
blank output; and a derived layer returns `null` rather than echoing its own input,
because the walker counts any non-null return as a hit.

### Other runtime facts

- A content script runs in an **isolated world**, so patching `history.pushState` does
  not intercept the page's own navigations. `src/spa-router.js` **polls**
  `location.pathname`; `popstate`/`pushState` are best-effort fast paths only.
- `globalThis.browser ?? globalThis.chrome` is the cross-browser API shim. Keep it.
- Permissions are deliberately minimal: `storage` + `host_permissions` on
  `app.billingo.hu` only. **No runtime network requests, no analytics, no telemetry** —
  see `PRIVACY.md`. Do not add a permission without an explicit reason.
- `<html data-bt-lang="en">` forces a language; it is the hook used by
  `tools/diagnose-extension.js` and `tools/stress-test.js`.

## Dictionary & build pipeline

Route → zone mapping lives in **`tools/zones.js` (single source of truth)** and is
compiled into `dict/_index.json`, sorted longest-prefix-first.

**Source of truth for translations is `dict/en.json` + `dict/fr.json`** (monolithic).
`dict/en/*.json` and `dict/fr/*.json` are **generated**; hand-edits to a shard are
destroyed on the next build. `build-shards.js` writes each shard then unlinks only the
files no longer in the plan, so a run that dies mid-write cannot leave `dict/<lang>/` empty.

Workflow to add coverage:

1. Add `"<hungarian>": "<translation>"` to `dict/en.json` **and** `dict/fr.json`.
2. Run `node tools/build-shards.js`.
3. Record any non-obvious fiscal/legal choice in `TRANSLATIONS.md` (dated entry).

**A capture-less run is safe and is a byte-exact no-op.** `tools/capture/` is gitignored,
so on a fresh clone `build-shards.js` rebuilds its zone baseline from the shard files
already on disk (`baselineObserved`), then overlays any `tools/capture/*.tsv` on top with
per-key precedence: a key seen in a capture takes the TSV's zones (so a fresh capture can
still move it out of `_common`), a key absent from the captures keeps its baseline zones
(so a partial TSV cannot collapse the dictionary into `_common`).

Three guards, each bypassable with `--allow-shrink`, cover a way the tool used to destroy
data silently:

- **structure** — refuses to write fewer shard files than exist on disk.
- **values** — refuses to lose more than `MAX_TRANSLATION_LOSS_RATIO` (10 %) of the
  non-empty values in either language. This is what catches `dict/fr.json` = `{}`, which
  the file count waved through with a reassuring "aucun shard modifié".
- **no evidence** — refuses to run with neither shards on disk nor a capture, the one
  state where the other two are vacuous (`3 < 0` is false, and a loss from 0 is not a loss).

The shards are our own output: they say **where** a key was seen, never **whether** it
exists. `dict/en.json` + `dict/fr.json` alone decide existence, so a deleted key stays
deleted instead of resurrecting from the shard written by the previous run. Candidate keys
are the **union** of both dictionaries' keys — a key translated on one side only (French
first, say) must not be dropped from the plan and then erased by the rewrite.

Filters (`tools/lib/filters.js`) are shared by the capture tools: `looksLikeNoise` rejects
code-shaped tokens and TypeScript doc-comment residue; `makeHuFilter` keeps a string only
if it carries a Hungarian diacritic or is already a dictionary key. Existing keys bypass
both filters, so a manually added accent-less key survives re-sharding.

Two things reject a **new** candidate before it can become a key:

- `hasHtmlMarkup` — a string carrying tags is rendered through `v-html`, so the browser
  parses it and it never appears verbatim in a text node: it can never match. Its useful
  text is captured separately, because `extractStrings` also emits the tag-stripped
  fragments. Deliberately **not** part of `looksLikeNoise`, which `extractStrings` tests on
  the whole string *before* mining those fragments — putting it there threw the text away too.
- **`dict/_rejected.json`** — a committed, per-string denylist with a reason. Hygiene
  decisions used to live nowhere, so every capture resurrected the same garbage (foreign
  date locales, dev doc-comments, demo-account names, internal fixtures, English strings
  captured on the key side). Adding an entry is a documented decision; removing one makes
  the string capturable again. It gates new candidates only — a key already in
  `dict/en.json` stays.

## Testing

`node:test` + `assert`. Pure logic is tested directly; DOM code runs under jsdom;
`src/*.js` is loaded via `tests/load-script.js` (`vm`) because it has no exports.
There is no lint or type-check, so the tests plus the packaging validation are the whole
safety net. Both run in CI (`.github/workflows/ci.yml`) on every push to `main` and every
pull request: `npm ci --ignore-scripts`, `npm test`, `npm run package`, `npm run lint:ext`.
`--ignore-scripts` is deliberate — playwright's postinstall pulls ~400 MB of browsers that
only `tools/` needs, never the tests.

`npm test` globs `tests/*.test.js`, one level, on purpose: `tests/**/*.test.js` is expanded
by neither POSIX `sh` nor bash without `globstar`, so it reached `node` as a literal and
relied on the test runner's own glob support — which varies by Node version and would have
broken CI on a different runner image.
Add a test for any change to the walker, the loader, the router, or the filters.

## Safety when crawling Billingo

`app.billingo.hu` is a **production invoicing app wired to NAV** (the Hungarian tax
authority), not a sandbox. Capture tooling must stay **strictly read-only**: open
dropdowns, add a client-side line item, then Escape. Never click a commit control —
no document issue, no draft save, no wizard "Tovább" (can start a real bank link), no
delete/confirm. This constraint is documented at the top of
`tools/crawl-interactive.js`; preserve it in any new tool.

## Conventions

- Comments in `src/` are English; several `tools/` files are commented in French —
  match the file you are editing rather than converting it.
- Every non-trivial behaviour carries a *why* comment. Keep that density.
- Console output in the runtime uses a `[bt]` / `[billingo-translator]` prefix and is
  limited to genuine warnings/errors.
- Conventional commits (`feat:`, `fix:`, `docs:`, `chore:` …), scoped where useful
  (`feat(dict):`, `feat(runtime):`).
- Trademark stance: this is an unofficial, unaffiliated tool. Keep that disclaimer
  intact in user-facing text.

## Known gaps (do not "rediscover" these)

- The legacy `/auth/login` page is served by a **separate v3 front-end**, not by Nuxt,
  so `/auth/*` is not a Nuxt route and `zoneForRoute('/auth/login')` is correctly `null`.
  Its rendered strings are nonetheless covered, because they live in `_common`. The Nuxt
  app has its own `/n/auth/*` routes (registration, activation, password reset, 2FA
  setup) and those DO have a zone — `auth` was removed from `EXCLUDE` in
  `tools/extract-bundle.js` once the bundle showed they are real user flows.
- `makeHuFilter` keeps a captured string only if it carries a Hungarian diacritic
  or is already a key, so **accent-less Hungarian is invisible to fresh DOM
  captures**. Those keys survive via the bundle's i18n catalog, not the DOM sweep.
- Interaction-gated text — validation errors, toasts, confirm dialogs — is out of
  reach of the crawlers, which are read-only against a production NAV-connected
  account. The bundle's i18n catalog now covers most of this class anyway: it is the
  authoritative string inventory and does not need the UI to be driven. A dedicated
  trial account would still unlock genuinely runtime-only text.
- Layers 7 (parenthetical) and 8 (separator) decompose arbitrary strings, so composite
  **user data** can be rewritten: a product literally named `Javítás (Autó)` renders as
  "Correction (Car)", because the dictionary maps `Javítás` to the invoice-correction
  sense. The all-parts-must-resolve guard kills the unknown-word cases (`Termék (Nagy)`)
  at a measured cost of 0–0.4 points on genuine UI composites, but it cannot help when
  every part happens to be a dictionary word. Closing it needs a container-level skip in
  `src/dom-walker.js` for line-item and preview cells; `SKIP_TEXT_TAGS` currently only
  covers `SCRIPT`/`STYLE`/`NOSCRIPT`/`TEXTAREA`.
- The committed shard **layout** is a function of (monolithic dicts, capture,
  *previous layout*), not of the versioned inputs alone — `mergeObserved` keeps a
  key's baseline zones when no capture mentions it. Rebuilding from scratch after
  deleting `dict/en/` and `dict/fr/` recovers every key and translation but places
  them differently, so "is the layout correct?" has no reproducible answer. It is a
  performance question only: `_common` loads first and `ensureAll` prefetches the rest.
- `createStats` refuses to count a string it recognises as its own output, which
  bounds one thing: 29 EN / 8 FR real misses in the app are byte-identical to
  something we emit, mostly accent-less or case variants of a Hungarian key we
  already translate (`Logo`←`Logó`, `Menu`←`Menü`, 24 country names). Those are
  dropped from the harvested miss list, so the "accent-less Hungarian is invisible"
  gap now extends from capture into the runtime export. The trade is heavily
  favourable — the same rule suppresses 712 EN strings that were Billingo's own
  English catalog polluting a list labelled "untranslated Hungarian".
- Bootstrap's tooltip `data-original-title` stash is deliberately **not** translated.
  Translating it broke the WeakMap-originals invariant: `_restoreTitle()` copies the
  stash into `title`, so our own value came back as an "external" write and was adopted
  as the element's original, freezing the tooltip in one language. Consequence of not
  mirroring: a tooltip Bootstrap initialised *before* our first walk flashes Hungarian on
  its first pop-up, then self-heals.
